# Дача: удалённый доступ к компьютеру через сайт

Тестовая версия: **файлы** (просмотр, скачивание, загрузка) и **экран** (живой поток + снимок).

```
Браузер ──HTTPS──> сервер (server/: вход + сайт) ──VPN──> агент на даче (agent/, Windows)
```

- `agent/` — запускается на дачном компьютере. Отдаёт только разрешённые папки и картинку экрана. Требует токен.
- `server/` — запускается на твоём сервере. Вход по логину и паролю, веб-интерфейс, проксирует запросы к агенту. Токен агента браузер никогда не видит.

## 1. Быстрая проверка на одном компьютере

Нужен Python 3.10+. Агент и сервер можно запустить на одной Windows-машине, чтобы просто посмотреть, как всё работает.

**Агент** (PowerShell):

```powershell
cd agent
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(32))"   # это значение — в AGENT_TOKEN
notepad .env                                                    # впиши токен и свои папки в ALLOWED_DIRS
python agent.py
```

Если экрана нет или хочется проверить только цепочку, поставь в `.env` `SCREEN_BACKEND=test`: вместо экрана пойдёт картинка-заглушка со счётчиком кадров.

**Сервер** (второе окно PowerShell):

```powershell
cd server
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python security.py                                              # спросит пароль и выдаст ADMIN_PASSWORD_HASH
python -c "import secrets; print(secrets.token_urlsafe(48))"   # это значение — в SESSION_SECRET
notepad .env
python server.py
```

Для проверки по `http://` в `server/.env` поставь:

```
AGENT_URL=http://127.0.0.1:8765
AGENT_TOKEN=<тот же токен, что у агента>
COOKIE_SECURE=0
TRUST_PROXY=0
```

Открой http://127.0.0.1:8000 и войди.

## 2. Боевая схема

1. **VPN между сервером и дачей** (WireGuard или Tailscale). Дачный компьютер подключается к серверу сам, порты на роутере открывать не нужно.
2. **Агент** слушает только VPN-адрес: в `agent/.env` `AGENT_HOST=<адрес в VPN>`. Не ставь `0.0.0.0`.
3. **Брандмауэр Windows**: разреши порт агента только из подсети VPN (подставь свою подсеть):
   ```
   netsh advfirewall firewall add rule name="DachaAgent" dir=in action=allow protocol=TCP localport=8765 remoteip=10.8.0.0/24
   ```
4. **Сервер** слушает только `127.0.0.1:8000`, наружу его выставляет Caddy (сам получит сертификат):
   ```
   dacha.example.com {
       reverse_proxy 127.0.0.1:8000 {
           flush_interval -1
       }
   }
   ```
   В `server/.env`: `AGENT_URL=http://<адрес дачи в VPN>:8765`, `COOKIE_SECURE=1`, `TRUST_PROXY=1`.
5. **Автозапуск агента.** Агент должен работать в сессии залогиненного пользователя, а не как настоящая служба Windows: служба живёт в изолированной сессии и не видит рабочий стол и камеру. Поэтому: включить автоматический вход в Windows и добавить задание «при входе в систему»:
   ```
   schtasks /Create /TN "DachaAgent" /SC ONLOGON /TR "\"C:\путь\agent\.venv\Scripts\python.exe\" \"C:\путь\agent\agent.py\""
   ```
   Окно консоли можно свернуть.
6. **Автозапуск сервера** на Linux: обычный systemd-юнит, который выполняет `python server.py` в папке `server/`.

## 3. Что уже сделано для безопасности

- Вход по паролю (хэш scrypt), блокировка IP на 15 минут после 5 неудачных попыток, пауза на каждую неудачу.
- Сессия в подписанной куке: `Secure`, `HttpOnly`, `SameSite=Strict`, живёт `SESSION_HOURS` часов. Дополнительно проверяется заголовок `Origin` у запросов-изменений.
- Агент отдаёт только файлы из `ALLOWED_DIRS`: пути нормализуются, выход через `..`, абсолютные пути и симлинки наружу блокируются. Файлы всегда скачиваются как вложение, а не открываются в браузере.
- Токен агента сравнивается за постоянное время; агент не стартует с коротким токеном.
- Строгая политика CSP, `X-Frame-Options: DENY`, `nosniff`, HSTS.

**Чего пока нет:**

- Двухфакторной аутентификации. Для сайта, который показывает твой экран, это следующий шаг. Либо поставить перед сайтом Cloudflare Access / Authelia, либо добавить TOTP.
- Принудительного завершения сессий. Кука подписана, но не хранится на сервере: сменить `SESSION_SECRET` значит разлогинить всех.
- Журнала действий.
- Ограничения попыток по IP, если ты не за прокси: тогда все запросы приходят с одного адреса.

## 4. Устройство и следующие шаги

| Файл | Что внутри |
|---|---|
| `agent/agent.py` | Файлы (`/files/list`, `/files/download`, `/files/upload`), экран (`/screen/stream` MJPEG, `/screen/snapshot`, `/screen/monitors`) |
| `server/server.py` | Вход, сессии, проксирование к агенту, защитные заголовки |
| `server/security.py` | Хэширование пароля, генератор хэша |
| `server/static/` | Веб-интерфейс (HTML, CSS, JS без сборки) |

Дальше по плану: камера (OpenCV → MJPEG, по аналогии с экраном), управление мышью и клавиатурой, включение по сети, 2FA.
